# AG Astro Motion Studio V1.4

Cinematic animation from one matching **starless image + star image / star mask**.
Built directly on the supplied V1.3.1 Performance Hotfix. Existing original-star
sprites, Numba acceleration, optional AI refinement, manual camera keyframes,
project files and encoder fallback remain available.

## Install and start

This package contains Python source and launch scripts, not a standalone EXE.
Extract the entire ZIP into a new folder. Use Python 3.10 or newer supported by
the dependencies (validated here with Python 3.12 on Linux).

- Windows: run `INSTALL_WINDOWS.bat`, then `START_WINDOWS.bat`.
- macOS: run `INSTALL_MAC.command`, then `START_MAC.command`; if needed use
  `chmod +x *.command` first.
- Linux: create a virtual environment, install `requirements.txt`, then run
  `python -m motionstudio.gui` inside that environment.

Re-run the installer when updating. Numba is required for fast CPU star
compositing. Its first render compiles the sprite kernel; subsequent renders
reuse it. Optional AI dependencies are separate in `requirements-ai.txt`.

## Quick cinematic workflow

1. Load a stretched starless image and its matching, pixel-aligned star mask.
   PNG/JPG, TIFF and FITS are supported. Both images must have the same dimensions.
2. Click **Generate Depth Maps**.
3. Enable **Cinematic Mode** and choose **Gentle**, **Cinematic**, **Deep 3D** or
   **Fly-through**. Adjust **3D Strength**, **Camera Motion**, **Star Motion** and
   **Atmosphere** as desired. These presets set the four sliders; they do not
   replace your camera keyframes or change the number of detected stars.
4. Select a **Loop Mode** and duration. Presets are 5, 8, 10, 15 and 20 seconds;
   type a custom whole-number duration from 1 to 600 seconds if needed.
5. Click **Preview Loop** for a lower-resolution animated preview. It repeats
   until stopped or another view/setting is selected. Scrubbing still previews
   an individual frame. Inspect the transition from the end to the beginning.
6. Choose output resolution/FPS and **Render MP4…**. Export saves the MP4 plus a
   project JSON and `.depth.npz` sidecar.

**Advanced Settings** reveals the original star controls, camera/keyframe editor,
AI options and additional cinematic depth controls. Cinematic Mode is optional
and initially off, preserving the familiar V1.3.1 workflow. The common depth
Generate button stays visible when advanced settings are collapsed.

## Cinematic controls

| Control | Default | Effect |
|---|---:|---|
| 3D Strength | 100% | 0–200%; scales the actual nebula and star Z distribution about Z=3 |
| Camera Motion | 100% | 0–200%; scales translation, rotations and FOV changes about the first camera keyframe |
| Star Motion | 100% | 0–200%; influences star depth spread and parallax, keeping the source catalog intact |
| Atmosphere | 25% | 0–100%; weak depth-dependent softness, desaturation and contrast reduction |
| Loop Mode | Off | Off, Ping-Pong, Seamless Orbit or Seamless Drift |
| Loop Duration | 8 s | Also controls export duration and rescales keyframe times |

| Preset | 3D Strength | Camera Motion | Star Motion | Atmosphere |
|---|---:|---:|---:|---:|
| Gentle | 70% | 60% | 70% | 15% |
| Cinematic | 110% | 100% | 100% | 30% |
| Deep 3D | 150% | 110% | 130% | 40% |
| Fly-through | 170% | 150% | 160% | 35% |

Increasing 3D Strength changes depth geometry rather than simply multiplying
camera movement. Zero strength puts all stars and nebula bands at the reference
plane. Nebula depth uses three overlapping soft bands with local depth variation.
Band depths follow the supplied depth map; a constant map does not invent
foreground/background separation. Layer weights normalize coverage to avoid
dark seams. Original image pixels are sampled; hidden nebula structures are not
reconstructed.

## Advanced depth and camera options

- **Depth Contrast** (0–200%, default 100%) modifies the depth map, not RGB contrast.
- **Depth Smoothing** (0–100%, default 40%) uses edge-preserving bilateral smoothing.
- **Nebula Layer Split** toggles the soft background/middle/foreground renderer.
- **Foreground Star Limit** (default 50%) softly limits how close larger observed
  stars can be placed. It never removes detected stars or changes star count.
- **Star Motion Blur** (default 15%) averages short depth-weighted star exposures.
  Distant stars stay sharper. Nebula pixels receive no motion blur.
- **Depth Haze** scales the atmospheric treatment. It works with layer splitting
  either enabled or disabled. Atmosphere does not generate new gas or dust.
- **Camera Path** offers Linear, Smooth and Cinematic. Cinematic uses time-aware
  cubic Hermite splines with continuous velocity through interior keyframes.
- **Automatic Cinematic Drift** adds small periodic X/Y and yaw/pitch variation.
  Camera Motion at zero removes drift and holds the first camera pose.
- **Keep Subject Centered**, on by default, aims the shared star/nebula camera
  at the image center using its processed nebula depth. It controls yaw/pitch;
  roll and FOV remain editable.
  It cannot identify an off-center subject or guarantee framing of an entire
  extended nebula at extreme FOV/zoom. Move the image's subject to its center first.
- Camera presets include Parallax, Push In, Pull Out, Side Drift, Orbit,
  Fly-through and Manual. Existing manual keyframes remain editable.

Drag the 3D preview to change yaw/pitch; with centering enabled, dragging adjusts
X/Y while keeping the center locked. The wheel changes Z. Use **Add / Replace at
time** to retain manual changes for export. Direct manual preview shows the pose
you are editing; the timeline/export applies the configured camera path and motion
scaling. Disable centering to use manually authored yaw/pitch.

**Off** follows the existing keyframes. **Ping-Pong** travels through them and
back, with smooth turns and no held endpoint frames. **Seamless Orbit** and
**Seamless Drift** create periodic closed motion using the extent of the edited
keyframe path; they do not traverse arbitrary intermediate keyframes. They do not
invent a camera path when all keyframes are identical, apart from optional drift.
At an exact full duration, the camera matches the initial transform. Loop export
samples `[0, duration)` so it does not add a duplicate first frame at the end.

## New projects and input switching

Use the small **Reset Project** button in Import to return to **No project loaded**.
It clears both inputs, labels, depth maps, AI state, protection mask, star catalog,
scene/preview caches, preview images, render status and camera keyframes. Camera
keyframes return to the default Parallax path for the selected duration. Cinematic
preferences and output settings remain available for the next project.

Reset never deletes or rewrites original image files. While an AI job, loop
preview generation or video export is running, reset/import are temporarily
disabled so an old worker cannot restore cleared project data.

You may also directly load a new image. If its resolution differs from the old
counterpart, the new image is kept and the old incompatible image is cleared.
Derived data is invalidated in both directions. A short status message asks for
the matching image; there is no fatal size-mismatch dialog. An invalid/unreadable
selection leaves the existing valid inputs intact. Depth generation is enabled
only for a valid matching pair.

## Original stars, performance and projects

Observed stars use their isolated original RGB sprites. Detection is done once at
source resolution, with deterministic individual depths and soft nebula protection.
The original Star Parallax, Star Depth Spread, Star Motion over Nebula, Star
Intensity, detection settings, Bloom and opt-in synthetic stars remain available.
Cinematic Mode never changes star count. Synthetic additions require the existing
explicit opt-in.

Fast Preview uses a longest side of up to 640 px, fewer layer iterations and two
motion-blur exposures. Final-quality Preview uses up to 900 px and final layer
iterations/four exposures. MP4 export uses the selected full output resolution,
the complete star catalog and bounded parallel frame workers. Animated loop
preview uses up to 480 px, normally 12 FPS and at most 240 cached frames (long
custom durations use a lower playback frame rate to bound memory).

All camera paths and loops use the same evaluator for preview and export. Each
frame is independent, preserving deterministic parallel rendering. CPU H.264 and
verified NVENC/Quick Sync/AMF fallback behavior are retained. Rendering is on CPU;
hardware encoding only accelerates video compression. Output is replaced only
after a successful encode.

Project schema 5 saves all cinematic controls, original camera keyframes, source
paths, nebula depth and protection. Older project schemas load with Cinematic Mode
off. Keep the JSON, `.depth.npz` and referenced originals available. Source images
are referenced, not embedded. Exported depth maps remain the underlying maps;
cinematic contrast/smoothing/strength are stored as non-destructive settings.

## Validation and scope

See **VALIDATION.md** for checks, measurements and platform limits, and
**GITHUB_RELEASE_NOTES.md** for English release notes. A reproducible synthetic
cinematic loop is included in `examples/cinematic_loop_demo.mp4`; it is a rendering
exercise, not a real astronomical observation. Earlier V1.3 documents are archived
in `docs/history`.

This remains an artistic 2.5D effect, not physically reconstructed volumetric gas
or measured astronomical distances. Strong depth/angles can cause resampling,
layer ghosting or reflected image borders. Start with Gentle/Cinematic and reduce
3D Strength or Camera Motion if needed. Manual depth sculpting, selectable subject
anchors, a separate Volumetric Look mode and more complex camera-path editing are
deferred. AI model download, actual Windows/macOS operation and real GPU encoders
were not validated in this Linux session. No source starless/mask pair from the
user was provided, so visual results on those originals still need review.
